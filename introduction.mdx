Ink Notes is a lightweight, terminal-first note-taking application built entirely in Python. It solves the everyday problem of needing a fast, keyboard-driven place to capture thoughts, code snippets, and references without ever leaving the terminal. The application is wired together with four focused libraries: [Click](https://click.palletsprojects.com/) for the command-line interface, [SQLAlchemy](https://www.sqlalchemy.org/) as the ORM backed by a zero-configuration SQLite database, [Pydantic](https://docs.pydantic.dev/) for strict input validation before any data touches the database, and [Rich](https://github.com/Textualize/rich) for beautifully formatted tables and panels in the terminal. Ink Notes runs on Windows, macOS, and Linux with a single `ink` entry-point command.

## Tech Stack

## Data Model

The `Note` class is a SQLAlchemy declarative model mapped to the `notes` table in a local SQLite database. Its fields are:

| Field        | Type                  | Details                                              |
|--------------|-----------------------|------------------------------------------------------|
| `id`         | `Integer` (PK)        | Auto-incrementing primary key, indexed               |
| `title`      | `String(100)`         | Required; maximum 100 characters                     |
| `content`    | `Text`                | Required; unrestricted length                        |
| `created_at` | `DateTime` (UTC)      | Set automatically on insert                          |
| `updated_at` | `DateTime` (UTC)      | Set on insert, automatically refreshed on every update |
| `tags`       | `JSON` (nullable)     | Optional list of tag strings                         |

<Note>
  Tags are stored as a native JSON array in the SQLite database column. This means they are persisted as a JSON-encoded list (e.g., `["python", "tips"]`) and decoded back to a Python `list[str]` by SQLAlchemy's `JSON` type on retrieval — no separate tags table or join is required.
</Note>

## Pydantic Schemas

Before any data is written to the database, Ink Notes validates it through one of two Pydantic v2 schemas defined in `ink/schemas.py`:

**`NoteCreate`** — used when adding a new note:
- `title`: required string, minimum 1 character, maximum 100 characters.
- `content`: required string, minimum 1 character.
- `tags`: optional `list[str]`; defaults to `None` if not provided.

**`NoteUpdate`** — used when modifying an existing note:
- `title`: optional string (`None` by default), minimum 1 character, maximum 100 characters if provided.
- `content`: optional string (`None` by default), minimum 1 character if provided.
- `tags`: optional `list[str]` (`None` by default).

All fields in `NoteUpdate` are optional so that callers can patch only the fields they need. Fields set to `None` are excluded from the update payload via `model_dump(exclude_none=True)`, ensuring untouched columns in the database are never overwritten.
